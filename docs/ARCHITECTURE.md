# Архитектура

Документ описывает, из каких частей состоит бот, как они взаимодействуют и почему
приняты текущие решения.

## Общая схема

```text
┌──────────────────┐        ┌──────────────────────┐
│ Пользователь ВК  │        │  Сообщество ВК       │
└────────┬─────────┘        └──────────┬───────────┘
         │ сообщение                   │
         └──────────────┬──────────────┘
                        ▼
              ┌───────────────────┐
              │ VK Long Poll API  │
              └─────────┬─────────┘
                        │ updates
                        ▼
              ┌───────────────────┐
              │ bot.py            │
              │ VKBotApp          │
              │ • фильтрация      │
              │ • команды         │
              │ • «печатает»      │
              │ • разбиение       │
              └─────────┬─────────┘
                        │ reply(peer_id, text)
                        ▼
              ┌───────────────────┐
              │ alina.py          │
              │ AlinaBot          │
              │ • история         │
              │ • RAG-контекст    │
              │ • промпт          │
              │ • CTA             │
              └───────┬───────────┘
                      │            ┌───────────────────┐
                      │            │ knowledge_base.py │
                      ├───────────►│ BM25 + стемминг   │
                      │            └─────────┬─────────┘
                      │                      │
                      ▼                      ▼
              ┌───────────────────┐   ┌───────────────────┐
              │ gigachat_client.py│   │ knowledge/        │
              │ OAuth + chat      │   │ zerocoder.md      │
              └─────────┬─────────┘   └───────────────────┘
                        │ HTTPS
                        ▼
              ┌───────────────────┐
              │ GigaChat API      │
              └───────────────────┘
```

## Компоненты

### `bot.py` — транспорт и жизненный цикл

- `VKClient` — минимальный клиент VK API (`messages.send`, `messages.setActivity`,
  `groups.getLongPollServer`, `groups.getLongPollSettings`).
- `VKBotApp` — основной цикл:
  - получает Long Poll сервер и переподключается при `ts`-ошибках;
  - игнорирует исходящие сообщения и дубликаты по `event_id`;
  - распознаёт команды сброса и помощи;
  - показывает статус «печатает», пока GigaChat формирует ответ;
  - разбивает длинные ответы по границам предложений (лимит VK — 4096 символов);
  - корректно завершается по `SIGINT` / `SIGTERM`.
- `main()` — разбор `--check`, загрузка настроек, сборка зависимостей, запуск.

### `alina.py` — логика консультанта

- `HistoryStore` — история диалогов в памяти:
  - хранит последние `HISTORY_TURNS` пар;
  - ограничивает длину каждого сообщения;
  - очищает диалоги по `HISTORY_TTL_MINUTES`.
- `AlinaBot.reply()`:
  1. валидирует и нормализует текст;
  2. получает историю пользователя;
  3. ищет релевантные разделы базы знаний;
  4. собирает system prompt: инструкции + факты + история;
  5. вызывает `GigaChatClient.chat()`;
  6. очищает markdown, добавляет ссылку на форму при лидовом интенте
     (с кулдауном `CTA_COOLDOWN_TURNS`);
  7. сохраняет пару в историю.
- `sanitize_for_vk()` — убирает markdown-разметку, которая не поддерживается ВК.

### `knowledge_base.py` — RAG без внешней векторной БД

- Загружает Markdown, режет на секции по `##`, длинные секции — на части.
- Токенизирует русский/английский текст и отсекает окончания.
- Строит обратный индекс и считает BM25.
- Расширяет запрос синонимами и добавляет бонус за совпадение с заголовком.
- Всегда включает «закреплённые» разделы (о компании, контакты).
- Ограничивает контекст `KB_MAX_CHARS`.

### `gigachat_client.py` — интеграция с LLM

- OAuth `POST /oauth` с `Authorization: Basic <credentials>` и `RqUID`.
- Кеширует access token и обновляет его за 2 минуты до истечения.
- Повторяет запрос при `401` (обновление токена) и `429/5xx` с backoff.
- Поддерживает корневой сертификат Минцифры через `GIGACHAT_CA_BUNDLE_FILE`.
- Никогда не пишет токены и тексты сообщений в лог.

### `config.py` — конфигурация

- Читает `.env` из корня проекта (или путь из `env_file`).
- Валидирует обязательные переменные и числовые диапазоны.
- Возвращает иммутабельный `Settings`.
- `configure_logging()` настраивает уровень и формат логов.

## Поток обработки сообщения

1. Long Poll отдаёт `message_new`.
2. `VKBotApp` проверяет, что сообщение входящее и не дубликат.
3. Команда (`старт`, `сброс`, `помощь`) обрабатывается без вызова LLM.
4. Иначе вызывается `AlinaBot.reply()`.
5. `KnowledgeBase.search()` возвращает top-K секций.
6. `GigaChatClient.chat()` получает system prompt и историю.
7. Ответ очищается, при необходимости дополняется CTA и разбивается на части.
8. `VKClient.send_message()` отправляет ответ.

## Принятые решения

| Решение | Альтернатива | Почему выбрано |
|---|---|---|
| Long Poll | Callback API | Не нужен публичный URL, домен и HTTPS |
| Локальный BM25 | Векторная БД / embeddings | Нет внешних зависимостей, предсказуемая стоимость, простота отладки |
| История в памяти | Redis / PostgreSQL | Минимум инфраструктуры; интерфейс `HistoryStore` легко заменить |
| `httpx` | `requests` / SDK | Асинхронность не нужна, но `httpx` удобен для таймаутов и тестов |
| Свой клиент GigaChat | Официальный SDK | Контроль над retry, кешем токена и логированием |

## Ограничения и направления развития

- Один процесс обслуживает одно сообщество.
- История не переживает перезапуск.
- Нет обработки изображений и документов.
- Нет метрик и health-check.
- Возможные шаги: Redis для истории, Docker, метрики Prometheus,
  A/B-тесты промптов, поддержка vision-моделей.
